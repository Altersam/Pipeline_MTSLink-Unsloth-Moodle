@moodle-lesson-builder

Обработай ВЕСЬ пакет уроков из папки:

"Z:/YandexDisk/Лицей/Цифровизация/Учебный процесс/Онлайн-уроки/.Обработка/Выгрузка 2/output/ТЕКУЩАЯ_ПАПКА/уроки"

Работай строго по skill `moodle-lesson-builder`.

Этот промт добавляет только правила запуска и оркестрации пакета. Содержание уроков, дизайн, Moodle HTML, предметные правила и QA бери из skill.

==================================================
1. NON-STOP MODE
==================================================

Обработай весь пакет за один агентный запуск.

Пока в `moodle_batch_status.json` существует хотя бы один урок со статусом:

- `in_progress`
или
- `queued`

НЕ возвращай финальный ответ пользователю.
НЕ останавливайся после одного урока.
НЕ жди сообщения `продолжай`.
НЕ спрашивай подтверждение перехода к следующему уроку.

После каждого урока:

SAVE HTML
→ QA
→ SAVE lesson_build_report.json
→ UPDATE moodle_batch_status.json
→ LOGICAL RESET
→ NEXT LESSON

Промежуточный прогресс не отправляй отдельным финальным сообщением в чат.

Источником прогресса является `moodle_batch_status.json`.

==================================================
2. WINDOWS PATH, НО НЕ ПРЕДПОЛАГАЙ WINDOWS SHELL
==================================================

Исходная файловая система пользователя — Windows.

Переданный путь с диском `Z:` является каноническим пользовательским путём.

Но shell/tool-среда может быть Windows CMD, PowerShell, Python, WSL/Linux или проксированной средой.

ROOT_PATH проверить максимум:

1. как передан;
2. с `/`;
3. с `\`.

Если один вариант работает — зафиксировать его и больше не переопределять.

ЗАПРЕЩЕНО:

- искать `/mnt/z`;
- искать `/media/z`;
- искать `/run/media/...`;
- менять диск;
- придумывать другой корень;
- сканировать файловую систему ради поиска `Z:`;
- рекурсивно искать YandexDisk.

Если ROOT_PATH недоступен после разрешённых проверок — остановить запуск и сообщить точную ошибку.

==================================================
3. НЕ НАГРУЖАЙ ФАЙЛОВУЮ СИСТЕМУ
==================================================

Для построения очереди прочитай только непосредственные дочерние папки ROOT_PATH.

Не используй без необходимости:

- повторные `cd`;
- повторные `pwd`;
- повторные `ls`;
- повторные `dir`;
- повторные `find`;
- `Get-ChildItem -Recurse`;
- `os.walk()` выше ROOT_PATH.

После определения ROOT_PATH используй абсолютные пути.

Предпочтительно вообще не использовать `cd` между уроками.

Одна и та же неуспешная файловая операция может быть повторена максимум 2 раза.

Если отдельная папка урока остаётся недоступной:

`status = needs_review`

`error_type = filesystem_access`

сохрани конкретную ошибку и переходи к следующему queued.

Одна проблемная папка не должна останавливать весь пакет.

==================================================
4. ОДИН УРОК = ОДИН РАБОЧИЙ КОНТЕКСТ
==================================================

Не загружай несколько уроков одновременно.

Для текущего урока используй только:

- skill;
- краткое состояние очереди;
- CURRENT_LESSON_PATH;
- `Расшифровка.txt`;
- `Запись.txt`;
- `files/`;
- существующий HTML текущего урока, если нужен.

После завершения:

- не перечитывай transcript;
- не перечитывай HTML;
- не переноси содержание в следующий урок;
- не используй tool-history прошлого урока как рабочий контекст.

Если среда умеет fresh context/subtask — используй.

Если не умеет — выполни логическое обнуление.

==================================================
5. БЕЗОПАСНОЕ СОХРАНЕНИЕ
==================================================

Для больших HTML и JSON избегай десятков мелких append-операций.

Предпочтительный цикл:

READ
→ ANALYZE
→ PLAN
→ BUILD
→ WRITE
→ READ BACK
→ QA
→ FIX
→ REPORT
→ STATUS
→ NEXT

Для status и больших HTML по возможности используй временный файл в той же папке и затем `replace/rename`.

Особенно важно не создавать большое количество мелких записей в синхронизируемой папке YandexDisk.

==================================================
6. ВОЗОБНОВЛЕНИЕ
==================================================

Если `moodle_batch_status.json` уже существует:

не начинай пакет заново.

Выбери:

первый `in_progress`;
если его нет — первый `queued`.

`done` не трогай.

Если у текущего `in_progress` уже есть частичный HTML — сначала проверь его и продолжи/исправь, а не создавай всё заново.

==================================================
7. КОНТЕКСТ
==================================================

Не выводи полный HTML в чат.

Не сохраняй длинные промежуточные рассуждения.

Не начинай новый урок, если текущий контекст почти заполнен.

Если контекст близок к пределу:

1. закончи текущий урок;
2. сохрани HTML;
3. выполни QA;
4. сохрани report/status;
5. создай fresh context/subtask, если возможно;
6. иначе выполни logical reset;
7. продолжи следующий урок.



==================================================
9. MOODLE/WAF SAFE PROFILE
==================================================

Для итогового урока используй только проверенный Moodle-safe подход:

HTML-фрагмент
+ inline CSS
+ таблицы
+ статический SVG
+ `<pre>/<code>`
+ `<details>/<summary>`
+ простой iframe записи из `Запись.txt`.

СТРОГО ЗАПРЕЩЕНО:

- `<script>`;
- `javascript:`;
- `onclick`, `onload`, `onerror` и любые `on...`;
- `srcdoc`;
- `data:text/html`;
- JS-обёртки;
- `<object>`;
- `<embed>`;
- внешние JS-библиотеки;
- активные виджеты;
- сырой HTML/JS внутри `<pre>`, если он не экранирован.

Код Python внутри `<pre>` безопасен и разрешён.

Если код содержит `<`, `>` или `&`, экранируй их как текст.

`<iframe>` использовать только для реального URL из `Запись.txt` и без JavaScript.

SVG делать статическим:
без `<script>`, обработчиков событий, `javascript:`, `foreignObject`.
По умолчанию не использовать `<animate>`/`<animateTransform>`.

Если требуется визуальная «анимация», замени её:
последовательностью статических кадров, шагами, timeline, before/after или схемой процесса.

Если красивая конструкция может вызвать WAF — выбери более простой безопасный HTML.

Проверенный стандарт имеет приоритет над дополнительной интерактивностью.

==================================================
10. ФИНАЛ
==================================================

Только когда больше нет `queued` и `in_progress`:

создай `moodle_batch_summary.json`

и верни ОДИН краткий итог:

- total
- done
- failed
- needs_review

Начинай с проверки ROOT_PATH, очереди и существующего `moodle_batch_status.json`.

Продолжай автоматически до конца пакета.

Не останавливайся после первого урока.
Не жди команды `продолжай`.
